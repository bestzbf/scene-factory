12 家店、114 张原图已处理成场景工厂的输入，**一家店一个场景、所有摄像头都输入**。场景工厂离线校验（`groups` 和 `run --dry-run`）全部通过，没有调用任何模型。

| 步骤 | 结果 |

## 怎么做的

- **时间戳**：数据里有两种样式，一种是带黑边的粗白字，按"白色字形 + 黑色描边"逐字找；另一种是细白字，用 macOS 自带的离线文字识别（Apple Vision，不联网）先找到日期/时间片段，再沿同一行补全没认出的字，最后按"YYYY-MM-DD HH:MM:SS"的固定版式补齐另一半。只修补笔画像素，不整块抹背景。
- **去畸变**：单参数除法模型。把被商品、交叉线打断的同一条货架边当作一条线一起评估，求出让它们最"直"、最"共线"的参数；把线段随机分成两半各估一次，两半一致才算可靠。本图不可靠时，借同店同分辨率（通常是同一型号摄像头）的结果。
- **缩放**：去畸变后输出与原图同尺寸、无黑边，再缩到长边 1280。

## 已知局限

- 时间戳修补在背景很花时会留下一小块色斑（修补本身的局限，比留着时间戳好）。偶尔会误把紧挨时间戳的招牌数字一起修掉。
- 720×576 的帧（模拟摄像头）画质低，单张去畸变估计噪声大，主要靠同店合并估计；同一家店混装不同焦距镜头时，合并估计是折中值。
- "和其他摄像头无重叠"（ISOLATED）标记只作参考：监控机位之间视角差很大，特征点匹配不上不代表不是同一家店。
- 文字识别依赖 macOS，批量处理需在这台 Mac 上跑。

## 运行方法

```bash
cd tools            # 仓库内；weidian_prep 是 tools/ 下的包
python -m weidian_prep.selftest
python -m weidian_prep.pipeline --raw pilot_20261029/raw --run-dir pilot_20261029/run_新目录
```

输出：`prepared/<店铺号>/<摄像头>.jpg`、`groups.json`（场景工厂直接读，场景 ID 就是店铺号）、`manifest.json`（每张图的来源哈希、时间戳框、λ 和来源、输出尺寸）。114 张约 60 秒；全量 12,212 张估计 2 小时左右。

## 场景工厂改动（0.3.43，未提交）

- 每个场景的视角上限从 16 改为 32（`multiview_spec.MAX_VIEWS`），校验、发给模型的 JSON schema、修复和报告统一引用这个常量；新增"25 个摄像头一个场景"的测试。全量测试 928 通过、123 跳过、0 失败。

## 批量建模前还没解决的

1. **模型调用的密钥**：最初提供的是腾讯云格式的密钥，不是模型网关的 key，没有使用。模型配置已写好（`production_local/factory_weidian_gpt61sol.json`：微店网关 `https://ai.vdian.net/openai`、Responses 接口、模型暂填 `gpt-6.1-sol`、key 从环境变量 `WEIDIAN_AI_API_KEY` 读）。
2. **零售资产**：生产资产库没有冷柜、收银台、收银机、满货架等，`library_layout_v1` 只能用库里已有类别，按评估报告的判断大部分店会在选资产时被拦。建议先拿这 12 家店真跑一次，看实际拦截率和渲染效果，再决定补哪些资产。
