# Demo 货架、入口与材质细化（2026-11-05）

本轮在上一轮批量版基础上继续优化，保留真实可编辑 3D、多机位共用几何和独立输出。参数配置为 `configs/retail/demo_batch_v2.json`，复用 `tools/batch/optimize_demo_batch.py` 与正式生成器的 `--retail-optimization` 接口。

## 可见改动

- 五家店补充按世界米制坐标映射的地砖接缝和粗糙度；1654871827 使用程序化水磨石颗粒。没有用照片投影地面。
- 四家店的货架增加真实网格的彩色价签条、小标签和细小印刷笔画。小标签用于陈列细节，不表达真实商品价格。
- 1654871827 的五组货架启用金属网架配置：移除原货架的非商品框架面，重建细立柱、侧面网格、薄层板和蓝色底座；保留商品及其支撑组位置。其依据是 view_03 中可见的白色线框侧架与蓝色底座。
- 1630174803、1649397835、1654871827 原场景的 front_wall=false 导致整个入口侧缺失，反向机位呈灰色空背景。本轮补上估计位置的双开玻璃门、门框、把手和两侧墙面。仅在源场景明确省略前墙且显式配置 entrance 时启用。门窗位置和尺寸仍是人工估计，没有完成摄影测量标定，也没有恢复室外环境。
- 包装背面和纸盒侧面增加固定 UV 印刷，减少反向机位的大块纯色。包装仍为通用程序图集，没有逐件恢复真实 SKU。
- 1646301141 保留上一轮 v5 专店重建，只应用本轮通用包装与地面细节，没有覆盖其已有门体和礼柜几何。

## 配置增量

`floor_tiles` 是每店可选字段：`color`（线性 RGB）、`size_m`、`grout_m`、`grout_color`、`roughness`、`terrazzo`。不指定则保留源地面。

`fixtures.<id>.shelf_edges` 支持 `color`、`height_m` 和 `wire_frame`。默认只加价签条；`wire_frame: true` 才会替换货架的非商品框架。仅用于确认是金属线框结构的货架，不应对所有资产默认开启。

`entrance` 支持 `width_m`、`height_m`、`center_x`；默认位于房间 y=0 边界。仅用于前墙原本省略的场景，尺寸必须在房间范围内。真实店铺入口不在这一面时不要套用该配置。

实现位于 `scene_factory/retail_visual_detail.py`，由共享优化阶段调用一次。批量输入指纹包含该模块，因此修改细节算法后不会错误复用旧结果。正式生成器在每个机位的 `retail_optimization.generated_geometry` 中记录新增入口和货架细节的实际世界包围盒；原有数据集对象 ID 不变。

## 运行方式

```sh
.venv/bin/python tools/batch/optimize_demo_batch.py \
  --source-root /path/to/demo_v3 \
  --out /path/to/new_output \
  --config configs/retail/demo_batch_v2.json \
  --source-override 1646301141=/path/to/demo_v5_geometry/1646301141 \
  --edge 1920 --samples 256
```

正式输出：`production_local/weidian_full_runs/demo_visual_v2_20261105/final_1920/`。不要用本轮优化后的工程再次执行同一优化阶段；重新调整应从原 v3 工程（1646301141 从 v5）开始。

## 验证与边界

初版小样的一致性检查捕获了新细节对象父子变换尚未刷新造成的哈希差异。修复为在记录渲染前几何指纹之前更新 Blender 依赖图，保留原检查强度。开发期间输入发生变化的小样目录标记失败，不能作为正式交付；正式图使用冻结的代码与配置单独生成。

本轮重点是修复可见结构缺失与陈列细节。货架长度、相机姿态、收银区内容、商品种类和数量仍存在误差；入口也只是估计几何。细化后的图更完整，不等于重建已准确。需结合原图、上一轮和本轮全部机位对比，不能只用首机位或单一图像分数验收。

本轮额外修复了生产标注的一个实际兼容问题：通用 `evaluated_bounds` 只遍历根节点的子对象，新门体是直接网格。现在新增细节使用自己的 evaluated mesh 包围盒函数，已在三个真实机位的标注中验证入口和五组金属网架记录。

可用以下命令生成“原图 / 上一轮 / 本轮”全机位对比及亮度、饱和度、SSIM、梯度结构分数：

```sh
.venv/bin/python tools/batch/review_retail_iteration.py \
  --previous /path/to/demo_batch_optimization_20261105/final_1920 \
  --current /path/to/demo_visual_v2_20261105/final_1920
```

各指标方向：亮度误差 `lum_err` 和饱和度误差 `sat_err` 越低越好，SSIM 与梯度结构分越高越好。它们衡量图像差异，不代表 3D 几何精度；明暗、颜色和结构可能出现相反变化。

## 正式结果

全部 5 家、43 个机位已完成 1920px / 256 spp 渲染，5 份共享几何一致性检查通过。再次运行原批量命令全部 `resumed: true`。6 项配置测试、14 项 Blender 回归测试通过；真实资产生产入口已输出三个机位的完整标注。

相对上一轮的平均 SSIM：1630174803 为 0.0964→0.0715，1646301141 为 0.1077→0.1076，1649397835 为 0.0050→0.0350，1654871827 为 0.1127→0.1745，1660108397 为 0.0048→0.0082。结构梯度指标仅 14/43 个机位上升；不能宣称所有机位的照片一致性都更好。1654871827 的网架和地面细化更有价值，但入口补齐改变了采光，亮度误差上升，需要后续联合校正照明与入口。1630174803 尤其需要进一步处理尺寸与机位，当前版本作为细节增强候选保留，上一轮工程不覆盖。

全机位“原图 / 上一轮 / 本轮”对比副本见 `docs/weidian/demo/visual_v2/`。完整结果与指标均保留下降项，真实几何与照片还原差距仍需继续缩小。
