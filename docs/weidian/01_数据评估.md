# 微店监控图作为场景工厂多视角输入的评估（2026-10-29）

数据：`cos://hd-ai-data/b300/data8/weidian/bg_frames_final/`（12,290 张，1,648 家店，5.77 GB）。
对照对象：scene-factory 0.3.42 的 `library_layout_v1` 资产库流程，以及生产资产库 `production_library_20261029`（583 件、136 类）。
本次只做了列目录、统计和抽样下载（共 73 张），没有调用任何模型 API。

## 结论

**结构上很合适，但现在直接跑会基本全部失败。** 原因有两个，按严重程度排：

1. **资产库缺核心的零售设施。** 场景程序的规则是：模型识别出的物体只要有一个类别在资产库里找不到资产，整个场景就被拦下（`missing_compatible_asset`）。便利店里几乎必有的饮料冷柜、收银台、收银机都没有对应资产，所以几乎每家店都会被拦。
2. **就算补上这些设施，外观也还原不出来。** 照片里占画面大头的是货架上成千上万件彩色商品。当前流程只能摆“一件件的物体”（每个场景最多 160 件），货架会渲染成空的，和照片差别很大。需要“已经摆满商品的货架、冷柜”这种整体资产。

另外还需要几项预处理（见下文），其中**去畸变**最重要。

## 一、输入结构：基本匹配

| 要求（来自代码） | 这批数据 | 判断 |
| --- | --- | --- |
| 同一文件夹的多张图视为同一空间 | 每家店一个文件夹，抽样里同店相机拍的是同一个店面，视角有重叠 | 符合 |
| 每个场景 1–16 张视角图 | 2–16 个相机的店有 1,579 家（96%） | 大部分符合 |
| | 超过 16 个相机的店 48 家（共 912 张，最多 25 个） | 需拆分或挑选 |
| | 只有 1 个相机的店 20 家 | 只能单视角 |
| 场景类型 | 便利店、小超市、烟酒店 | `shop` 类型已支持 |
| 房间尺寸上限 30×40×8 m | 小店一般不超过 10 m；25 个相机的超市约十几米 | 符合 |
| 每个场景最多 160 件物体 | 以货架、冷柜为单位计，小店几十件 | 符合 |

每家店的相机数，统计到 1,647 家、12,212 张，有 78 张文件名是摄像机型号格式，没被统计脚本匹配到，约占 0.6%：

| 相机数 | 1 | 2–3 | 4–6 | 7–9 | 10–16 | >16 |
| --- | --- | --- | --- | --- | --- | --- |
| 店铺数 | 20 | 144 | 645 | 434 | 356 | 48 |

逐店数字见 `shop_camera_counts.json`。

## 二、资产缺口

把 30 家店随机各取一张，按画面里能看到的东西粗略统计（单张画面只拍到店的一部分，整店的出现率会更高）：

| 店内物体 | 30 张里大约出现 | 生产资产库现状 | 缺口 |
| --- | --- | --- | --- |
| 摆满商品的岛柜/货架（双面） | 几乎每张 | 只有 8 件空书架、铁架 | **缺“满货架”资产** |
| 摆满商品的靠墙货架 | 很常见 | 同上 | **缺** |
| 收银台 | 约一半 | 无 | **缺** |
| 收银机 / POS / 扫码设备（放台面上） | 约三分之一 | 无 | **缺** |
| 玻璃门饮料冷柜 | 约四分之一（整店里更常见） | 无 | **缺** |
| 卧式冰柜（雪糕柜） | 偶见 | 无 | **缺** |
| 烟柜 / 玻璃展示柜台 | 约六分之一，烟酒店为主 | 只有 5 件木柜，样式不对 | **缺** |
| 酒水展示架 | 烟酒店常见 | 无 | 缺 |
| 整箱饮料、桶装水、纸箱（落地） | 常见 | 只有 1 件纸箱、几件木箱 | 不足 |
| 散装零食盒、购物篮叠放 | 偶见 | 无 | 缺 |
| 凳子、办公椅、风扇、垃圾桶 | 偶见 | 有凳子、椅子、储物桶；无风扇 | 基本够 |
| 沙发、茶几、圆桌（茶叶店等） | 少数 | 有 | 够 |

这些东西不在静态流程的支持范围内，记为“未建模”即可，不需要资产：吊顶灯、吊挂招牌、挂墙电视、空调、海报、监控摄像头本身。

**建议补的第一批零售资产**（按出现频率排序；尺寸以常见规格为准，生产时按实物测量）：

| 类别（建议名） | 摆放 | 常见尺寸（长×深×高，m） | 说明 |
| --- | --- | --- | --- |
| `stocked_gondola_shelf` | 落地 | 1.2×0.9×1.6 左右，双面 | 必须带商品，至少几种配色和货品组合 |
| `stocked_wall_shelf` | 落地 | 1.0×0.45×2.0 左右 | 带商品 |
| `beverage_cooler` | 落地 | 单门 0.6×0.6×2.0，双门约 1.2 宽 | 玻璃门内带饮料 |
| `checkout_counter` | 落地 | 1.2–2.0×0.6×0.9 | 台面要能测出支撑面，才能放收银机 |
| `pos_terminal` | 台面 | 0.35×0.3×0.4 | 屏幕、扫码枪、钱箱 |
| `chest_freezer` | 落地 | 1.0–1.6×0.65×0.85 | 玻璃顶，带雪糕 |
| `cigarette_cabinet` | 落地 | 1.0×0.5×1.0 / 2.0 | 玻璃柜台、背柜两种 |
| `drink_case_stack` | 落地 | 0.4×0.3×0.3 起，可堆叠 | 整箱饮料、桶装水 |

如果只用于这批数据，建议单独建一个“零售”资产库版本，而不是混进现有 136 类的库：模型收到的类别提示会短很多（现在约 2.5 万字符），也不会混入雨伞、凉亭这类无关类别。

## 三、预处理

| 问题 | 情况 | 影响 | 建议 |
| --- | --- | --- | --- |
| **广角桶形畸变** | 相当普遍，30 张里至少 7–8 张非常明显 | 场景工厂的相机是不带畸变的针孔模型，畸变越大，相机估计和渲染对位越不准 | 入库前去畸变：有摄像机型号的按型号镜头参数，其余用直线约束自动估计；最低限度先裁掉畸变最重的边缘 |
| **画面叠字** | 绝大多数右上角有时间戳，个别有绿色检测框 | 会被当成画面内容，也干扰色调匹配 | 遮挡或修补右上角时间戳区域 |
| **分辨率混杂** | 1280×720、1920×1080、720×576 都有；说明文件写的“统一 1280×720”不准确 | 原图会按原尺寸发给模型，1080p 图的像素约是 720p 的 2.25 倍 | 统一缩到最长边 1280，减少 token，也让各视角一致 |
| **超过 16 个相机** | 48 家店 | 超出单场景上限 | 按画面重叠把相机分成几个区域各成一个场景，或每店挑 16 个覆盖最好的视角 |
| **无效视角** | 个别相机只拍到收银台台面特写或天花板 | 浪费 token、干扰重建 | 按画面内容过滤 |
| **单视角店** | 20 家 | 只能单视角重建 | 可以保留，但质量预期要低 |

## 四、使用限制

- README 写明“仅供研究和学习使用”，数据来源是微店监控系统。用它生成的场景和数据集应沿用同样的限制。
- 画面里没有人（已经过两个模型筛选），但有店名招牌、二维码、收银屏幕等信息。对外发布前要再评估。

## 五、建议的推进顺序

1. **先补零售资产**：按上表的第一批 8 类，各做几种变体，入库到单独的零售资产库版本。
2. **同时做预处理**：去畸变、遮挡时间戳、统一缩放、拆分大店。这部分不需要 API，可以先做。
3. **小规模试点**：挑 20 家 4–8 个相机、畸变较小的店，用 GLM 跑一遍，看相机估计和外观还原的实际效果，再决定是否全量。
