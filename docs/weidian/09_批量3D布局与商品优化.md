# 批量 3D 布局与商品优化（2026-11-05）

本轮覆盖 5 家 demo 的全部 43 个机位：1630174803（10）、1646301141（8）、1649397835（12）、1654871827（3）、1660108397（10）。目标是真实可编辑 3D 和跨机位一致性；几何只构建一次，随后切换相机。照片不作为面向相机的投影替代场景。

## 本轮改动

- `scene_factory/retail_refinement.py`：生产生成器和已有场景共用的确定性优化阶段。按商品材质识别导入网格中的货品，保留其他材质的货架框架；将方块商品按类别细化为瓶、软袋、纸盒，使用固定物体 UV。未知连通结构跳过并报告，避免误删框架。
- `retail_stock_geometry.py`：抽出原单店脚本的网格生成器，使单店修正和通用商品优化复用相同实现。
- 支撑关系递归移动：货架、托盘和托盘上的商品按 `support_id` 传递关系一起平移。原资产选择阶段省略的对象单独记录，不生成不存在的商品。只允许水平移动，避免 XY 布局无法表达高度偏移。
- 配置指定的货架顶层增加实物商品，避开已有商品和声明的支撑物；这不是从照片自动恢复每个 SKU。
- 布局保护：用实际物体的世界 AABB 比较移动前后，拒绝新增显著货架重叠和房间越界。已有重叠、细网格碰撞、人员通行规范不在此检测保证内。

## 已有场景批量入口

在仓库根目录执行（使用安装了 Pillow / NumPy 的 Python）：

```sh
.venv/bin/python tools/batch/optimize_demo_batch.py \
  --source-root /path/to/demo_v3 \
  --out /path/to/new_output \
  --config configs/retail/demo_batch_v1.json \
  --source-override 1646301141=/path/to/demo_v5_geometry/1646301141 \
  --edge 1920 --samples 256
```

自动发现包含 `scene.blend` 和 `scene_bundle.json` 的子目录，默认渲染所有机位。`--shops ID ...` 限定店铺，`--views view_01 ...` 用于预览。`--source-override SHOP=PATH` 可重复，显式保留已有专家修正工程。没有 v5 工程时可以省略该项，但 1646301141 将从 v3 开始，效果不等同于本次交付。

默认 Blender 路径为 macOS 安装位置，可用 `--blender` 或 `BLENDER` 覆盖。每店超时默认 7200 秒，可用 `--timeout` 修改。

- 每店独立日志与错误记录，某店失败后继续其余店，最终有失败则进程退出码为 1。
- 原工程不写入。输出与输入必须独立，已有输出输入指纹不一致时拒绝覆盖。
- 完整输出、校验通过且指纹相同时直接跳过。指纹包含源 blend、bundle、布局、商品图集、配置、核心优化源码、机位和画质；中断后可用原命令继续。失败但输入未变化时重跑该店。
- 图集来自仓库内程序绘制的通用包装，不调用生图或其他付费模型。没有指定图集时，批量入口自动生成固定种子的图集；直接调用生产优化阶段需要显式提供图集。

## 接入正常生产渲染

`scene_factory/generate_multiview.py` 新增可选参数：

```sh
Blender -b --factory-startup --python-exit-code 1 \
  --python scene_factory/generate_multiview.py -- \
  --spec /path/to/scene_bundle.json \
  --output-dir /path/to/new_output \
  --texture-manifest /path/to/textures/manifest.json \
  --asset-catalog /path/to/asset_catalog.json \
  --asset-bindings /path/to/asset_bindings.json \
  --retail-optimization configs/retail/demo_batch_v1.json \
  --retail-layout /path/to/initial_layout.json
```

顺序为：构建共享场景 → 优化商品与布局 → 几何预检 → 色调校准 → 保存工程 → 所有机位的标注与渲染。物体位置及标注 AABB 取优化后的真实几何。原 spec 和原图片哈希保留，派生配置及优化报告进入 provenance，另写 `optimized_bundle.json`。原参数不开启该阶段时沿用现有流程。

`tools/batch/render_demo.py` 同样接受 `--retail-optimization`，并转发原布局。

现有 `tools/batch/render_offline.py` 保留原位置参数，使用环境变量接入：

```sh
RETAIL_OPTIMIZATION="$PWD/configs/retail/demo_batch_v1.json" \
  .venv/bin/python tools/batch/render_offline.py RUN_DIR CATALOG_JSON NEW_OUT
```

处理新的批量店铺时，可以建立更小的配置，只保留 `schema_version: 1`、`seed`、`atlas`、`defaults` 和空 `scenes`。`atlas` 相对配置文件所在目录解析。新店未知 ID 不要复制 demo 专店覆盖；配置中不存在于当前场景的 fixture ID 会明确报错。

本次没有重跑全部 494 家店。应先抽样通过正常生产预检，再按原批量流程投产。

## 配置格式

```json
{
  "schema_version": 1,
  "seed": 17,
  "atlas": "packaging_print.png",
  "defaults": {"fixtures": {}},
  "scenes": {
    "shop_id": {
      "fixtures": {
        "central_gondola": {"kind": "snack", "top_stock": true}
      },
      "moves": [{
        "id": "central_gondola",
        "translation_m": [-0.2, 0, 0],
        "evidence": "Reviewed against forward and reverse references"
      }]
    }
  }
}
```

商品类型：`mixed`、`snack`、`beverage`、`household`、`gift`、`tobacco`、`preserve`。`preserve` 或 `enabled: false` 保留原货架商品。顶层补货仅显式启用的货架执行。

## 输出与验证

本地正式输出：

`production_local/weidian_full_runs/demo_batch_optimization_20261105/final_1920/`

每店保存可编辑并打包纹理的 `scene.blend`、全部 `rgb_view_*.png`、`scene_bundle.json`、`optimization_config.json`、`refined_layout.json`、`retail_refinement.json`、`verification.json`、`batch_state.json` 和日志。

`scene_bundle.json` 表达源基础对象与位移；新增瓶袋和顶层陈列的完整几何以 blend 为准。此已有工程入口用于优化工程及效果审阅；需要数据集标准标注时使用上面的正常生产渲染入口重新生成，不要沿用旧版 annotations。

- `all_shops_review.jpg`：每店首末机位，三列依次是原图、v3、优化后的共享 3D。
- 每店 `all_views_review.jpg`：全部机位的同样对比。
- `retail_refinement.json`：替换件数、补货件数、位移支撑组、跳过原因与布局保护结果。
- `verification.json`：有限坐标、原相机保留、全部机位前后几何坐标/物体变换 SHA256 一致、单次几何构建和纹理打包统计。这些检查证明工程一致性，不证明照片还原精度。

验证包括 5 项配置/支撑图/布局保护单元测试、14 项现有 Blender 多视图与几何预检测试、带真实资产的生产入口 smoke test，以及原 v5 专店构建脚本的小图回归。

## 仍然存在的差距

包装是通用类别外观，商品身份、单品数量和摆放并未逐项恢复。多家店的柜体样式、门窗和货架密度、相机位置、收银区域及堆货仍与原图不同；尤其 1649397835 的后墙陈列比例、1654871827 的货架细结构及 1660108397 的前区内容仍需继续校正。不能用“全部机位一致”替代“布局与照片准确”。下一阶段应增加带多视图证据的房间/货架尺寸和相机联合校正，以及更贴近照片的可编辑资产种类。
