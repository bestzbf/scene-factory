# 资产库驱动的批量场景生产（0.3.43）

本配置使用 `library_layout_v1`：每个场景将一张或一组照片发送给模型一次，返回完整的房间、相机、灯光、物体类别、尺寸及支撑关系 JSON。固定程序负责选取资产、计算摆放、检查、Blender 渲染和保存。模型返回的内容不会作为代码执行。

## 开始使用

从新建项目目录运行下面命令。若已有符合运行时协议的目录，可以直接配置 `asset_library.catalog`；若持有最简两文件资产包，先离线入库一次。

```sh
scene-factory assets-import --input-dir asset_packages --output-dir assets
scene-factory doctor --config factory.json
scene-factory run --config factory.json --input-dir photos --output-dir output --dry-run
scene-factory run --config factory.json --input-dir photos --output-dir output
scene-factory status output
scene-factory usage output
scene-factory report output
```

`assets-import`、`doctor`、`--dry-run`、状态与报告均不调用模型。正式 `run` 将照片发给配置的模型服务。先在本机环境变量 `SCENE_API_KEY` 配置专用密钥；不要写进配置、资产或仓库。可在 `models.analysis` 更换支持图片和 JSON 的模型、服务地址及密钥环境变量。

单独的照片放 `photos/` 根目录；同一空间的多个视角放同一个子目录，每组最多 16 张。每组只生成一个共享三维场景，保留对应相机。不同空间必须放不同组。

若用现有项目启动器，可选“资产库模式”。它有独立配置与输出目录，不会复用旧内置模型流程的结果。

## 资产交付与自动入库

每件物体一个目录，目录名是全库唯一 ID，例如 `chair_000123`。同一物体的不同几何或外观分别作为独立资产包，最容易批量生产，也避免给不兼容的网格套错纹理。

```text
asset_packages/
  chair_000123/
    model.glb
    asset.json
  chair_000124/
    model.glb
    asset.json
```

`asset.json` 只有五项：

```json
{
  "schema_version": "scene_asset_input_v1",
  "category": "chair",
  "placement": "floor",
  "longest_dimension_m": 0.9,
  "scale_source": "estimated"
}
```

- `category`：小写 snake_case，同类使用同一个类名。程序按类别精确检索。
- `placement`：`floor`（地面）或 `surface`（物体支撑面）。
- `longest_dimension_m`：规范姿态下包围盒三轴中最长的一边，单位米，不是对角线。
- `scale_source`：`measured`、`known_reference` 或 `estimated`，如实填写。
- GLB：一件完整静态物体，Blender 导入后 +Z 向上、语义正面 -Y、处于正常使用姿态；使用内嵌纹理、第一 UV、标准不透明 glTF metallic-roughness PBR。当前严格入口不接收透明、发光、骨骼、动画、morph、特殊材质扩展或外部贴图引用。

程序等比缩放、把底部中心归零，保存正规化 GLB、哈希、尺寸、入库收据和原生材质记录。失败的资产写入 `intake_report.json` 并隔离，不阻断其他资产。再次运行会复用未变且完整的产物。更改原资产或入库实现后，请用新的资产库版本目录；不要直接覆盖正在使用的库。

支撑区域从实际网格计算，不依赖包围盒顶部。严格共面区域优先使用；对网格细分造成的轻微起伏，还会尝试保守的近水平检测：候选面高度带不超过 1 mm、拟合坡度不超过 0.003、投影三角形并集完整覆盖矩形足印，并排除孔洞、缺口、遮挡和上方悬挑。桌面区域需通过可见性采样，记录实测高度和二维范围。几何不满足条件时会拒绝支撑关系，不虚构高度，也不会用盒子替代。检测证据只证明所记录的几何范围，不是负载能力、稳定性或物理仿真保证；弧面、台阶、复杂遮挡仍可能没有可用区域。

入库状态为 `technical_ready`。该状态表示格式、尺寸变换、导入和材质等技术检查通过，不等于语义完整、真实尺度准确或视觉验收通过。

## 自动装配规则

模型只收到类别、数量、尺寸范围和支撑能力摘要，不收到整库模型路径、资产 ID 或全部材质信息。摘要大小主要取决于类别数，当前最多 256 类；超出会明确报错，应按项目拆分目录。批次内复用类别索引与摘要，渲染前复查选中资产依赖。

布局给出实例 ID、类别、XY、目标尺寸、绕 Z 角度和 `support_id`。程序从同类资产中筛选尺寸相近且技术合格的候选，仅允许等比缩放。地面物体底部为 Z=0；支撑物上方物体按实际选中资产的支撑面重新计算 Z，并要求整个占地范围落在支撑区域内。更换桌子高度后，小物高度随之改变。

选取结果、材料版本、缩放、来源、尺寸误差和失败原因保存在每个场景的 `iteration_00/asset_selection.json`。不满足条件的场景不会用默认盒子冒充资产完成渲染。

默认按照尺寸误差和稳定种子选取。`asset_library.selection.diversity=true` 可优先减少同一场景内已用几何/材质组合的重复，再比较尺寸误差；所有候选仍须通过尺寸限制。固定种子与场景 ID 保持续跑确定性。它不是照片外观相似度检索，也不保证跨全部场景均匀使用资产。

场景检查包括完整占地的房间边界、支撑图和保守旋转包围盒重叠。父子支撑对象之间不做普通包围盒碰撞，避免桌腿包围盒误报桌上小物；这不是逐三角网格物理仿真。失败场景保留模型输出及原因，不自动移动物体来掩盖错误。

## 用量、并发和续跑

该模式强制每场景请求预算为 1、API 重试为 0、JSON 验证重试为 0、视觉复审关闭、自动修正为 0。提示输出上限默认 12288 token；输入图、提示和模型推理仍会产生用量，输出上限不等于总 token 上限或总费用。

完成的响应和分析记录会保存。如果传输已完成而本地提交中断，可以恢复本地提交；若不能确认响应完成，则不会自动再次发送付费请求。布局不合法、缺资产或摆放失败时也不会再次询问模型。

重复相同 `run` 命令可继续本地未完成步骤；已完成且所有输入、配置、代码和依赖哈希相同的场景直接复用。更换模型、参数、代码或库版本请使用新输出目录。不要手动删除预算或来源记录来强制续跑。

`batch.workers` 控制场景并行，`api_workers` 控制模型并发，`render_workers` 控制 Blender 并发。初次在本机从 1/1/1 开始，先看内存和 API 限流再提升。原有请求账本、限流、熔断、磁盘检查和分片共享账本继续生效；生产配置可显式设置 `batch.min_free_disk_bytes` 和 `batch_budget`。

每个成功场景包含 `.blend`、各视角 PNG、布局 JSON、资产绑定、渲染来源记录和结果状态。批次报告列出成功与失败；某场景缺资产不会伪装成验收成功。

## 结果如何解释

关闭视觉复审的成功结果是 `generated_unreviewed`，可查看和继续编辑；`accepted.json` 和正式 `export` 不收录这些场景。技术入库和本地几何检查都不能替代原图还原验收。

当前资产模式适用于矩形室内空间的静态、不透明、地面或支撑面物体。墙挂、吊挂、玻璃、镜面/特殊材质、复杂建筑开洞、外观嵌入检索和全网格物理碰撞仍需后续扩展。新流程不会自动调用旧的 canonical 修正器，避免修正后丢失资产支撑关系。

本地模拟 API 加真实 Blender 测试可以证明装配、渲染、失败隔离与续跑链路；不证明模型能正确理解任意照片，也不等于已经完成万级真实 API 试产。大量正式投产前应对代表性照片和真实资产库做分批验证。
